=====================================================================================CRUCIAL NOTE=================================================================================

 * Un Server Component peut appeler directement les fonctions d'un fichier data.ts pour lire la base, sans passer par une API(ou un route handler).

 * Un server component qui traite du formulaire(ou effectue une mutaion-écrire dans la base: créer, modifier ou supprimer des données-) peut utiliser directement des 'server action' fonction pour l'interaction avec la base de données.(voir app/lib/actions.ts

 * Un Client Component ne peut pas(ou dois pas) accéder directement à la base de données(aux fonctions d'interaction avec la base de données pour lire les données-dans un fichier data.ts par exempls-)pour lire les données : il doit utiliser un Route Handler 
 * Pour créer, modifier ou supprimer des données,un Client Component peut déclencher une Server Action ou passer par un route handler

 * Une Server Action importée dans un Client Component doit être définie dans un fichier séparé marqué "use server".



Client Component + FastAPI :
- fetch direct autorisé ;
- Route Handler facultatif comme intermédiaire ;
- Server Action surtout pour les mutations.

Server Component + FastAPI :
- fetch direct recommandé ;
- Route Handler généralement inutile ;
- Server Action utile pour une mutation déclenchée par l’utilisateur,
  mais inutile pour une simple lecture pendant le rendu.

/**
 * DOSSIERS PRIVÉS ET SEGMENTS DE ROUTE DANS NEXT.JS
 *
 * Dans le dossier app/, les sous-dossiers représentent les segments
 * qui permettent de construire l'arborescence des routes.
 *
 * Un segment devient une page accessible lorsqu'il contient un page.js
 * (ou page.jsx, page.tsx).
 *
 * Exemple :
 *
 * app/
 * └── blog/
 *     └── page.js
 *
 * → accessible avec : /blog
 *
 *
 * DOSSIER PRIVÉ (_folder) :
 *
 * Si le nom d'un dossier commence par un underscore "_",
 * Next.js considère ce dossier comme un dossier privé (Private Folder).
 *
 * Exemple :
 *
 * app/
 * └── _components/
 *     └── page.js
 *
 * Même s'il contient page.js, ce dossier et ses sous-dossiers
 * sont exclus du système de routage.
 *
 * Donc :
 * /_components   ❌
 * /components    ❌
 *
 * Cela permet d'organiser et de colocaliser dans app/ des fichiers
 * ou composants qui ne doivent pas devenir des routes.
 *
 * À retenir :
 *
 * blog/         → peut participer au routage
 * _components/  → dossier privé, exclu du routage
 *
 * Le "_" signifie donc à Next.js :
 * "ce dossier sert à l'organisation du projet, pas au routage."
 */
